# ADR-0001: 必达停在番茄钟、录音和宏事件

- 状态：已采纳
- 日期：2026-11-01
- 决策人：待填写　协助：Grok
- 关联需求：REQ-001、REQ-201、REQ-202、REQ-203、REQ-204、REQ-205、REQ-206

## 背景

设想里还有 TF 卡、蓝牙 HID、蓝牙传文件、大模型待办、神经网络 VAD 和外壳。课程套件没有卡、电池和马达。写代码的机器没有 SDK，固件编不过。

## 备选方案

| 方案 | 优点 | 缺点 | 对需求/风险的影响 |
|---|---|---|---|
| A. 本期把小智整条链路接上 | 板上已经有录音和蓝牙 | 产品变成另一个对话助手，仓库还要吃下约 201MB 的包 | P0 会被挡住 |
| B. 必达只做能在主机上测完、板上能看出来的闭环 | 范围清楚，测试能写实 | 掉电没有录音，电脑音量不会真的变 | 拓展保留编号，不删除 |

## 决策

选择 **B**。

理由：先让立起计时、扣下安静、按一下能留下去掉静音的 WAV、侧放能发出宏事件。做不到的硬件不写进必达。

## 后果

- 正面：`capsule/` 不依赖 SDK 就能测。
- 负面/代价：复位后录音消失。宏事件不会改变电脑。
- 需要同步修改：需求、设计和测试里 P2 保持未开始。

## AI协作

agent 对照课程手册和套件清单建议收小范围。学生后来确认小智整包不入库。没有把未做的板端测试写成通过。
