# 架构决策记录（ADR）

每个**有取舍**的关键决策写一份 ADR，一决策一文件，命名 `NNNN-短标题.md`（从 0001 起）。

## 什么时候要写

- 选型：外设/总线/协议/库的选择（如 BLE vs 离线导出、LVGL 控件方案）
- 架构：模块划分、线程模型、数据流
- 改变了 PRD 或设计的决定
- 否决了 agent 的建议、或接受了 agent 的建议但有保留

## 规则

1. 决策**必须由人拍板**；agent 可以提供备选与权衡。
2. 已采纳的 ADR 不要改写历史，要变更就新建一份并把旧的标记为“已废弃（被 ADR-xxxx 取代）”。
3. 在 `docs/02-方案设计说明.md` 的决策表里引用。
4. 提交类型用 `docs(adr)`。
