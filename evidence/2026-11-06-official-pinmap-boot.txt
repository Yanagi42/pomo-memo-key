# 2026-11-06 official board pin-map correction and UART boot

- Reference: LCSC Huangshan Pai hardware page `https://wiki.lckfb.com/zh-hans/hspi-sf32lb52/hardware/board.html`.
- Official mapping: PA40 = sensor I2C1_SCL, PA39 = sensor I2C1_SDA; PA37 = touch I2C_SCL, PA33 = touch I2C_SDA. The previous PA33/PA37 IMU change was wrong and caused `read id failed` / `startup blocked`.
- Corrected firmware: IMU initialization and each raw IMU read use PA40/PA39; the read restores PA33/PA37 for the SDK FT6146 touch driver. The UI does not remap pins; SDK `BSP_PIN_Touch` owns PA33/PA37.
- Build: `scons --board=sf32lb52-lchspi-ulp -j8` exit code 0.
- Flash: `sftool -p /dev/ttyUSB0 -c SF32LB52 -m nor write_flash --verify bootloader/bootloader.bin@0x12010000 main.bin@0x12020000 ftab/ftab.bin@0x12000000` exit code 0.
- Reset: followed the official board procedure by pulsing UART RTS high then low at 1,000,000 baud.
- Boot evidence: `v0.4.2 boot ok`, `capsule selftest PASS (0)`, `IMU ready`, FT6146 probe/open succeeded, `UI ready`, display turned on. A 35-second UART capture contained zero `i2c_stat` errors and zero `i2c sem timeout` messages.
- Remaining: physical screen layout and a real touch click still require manual interaction; no touch event was generated by the host.
